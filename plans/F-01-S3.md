## Goal

Postgres becomes a faithful copy of each project repo's records and links, rebuilt on every push. It hands out IDs safely to parallel runs, and answers the queries the MCP tools and dashboard need. Git stays the record.

## Build

Add `@factory/records: workspace:*` to `packages/db` and `apps/dashboard` dependencies, and `@factory/records` to the dashboard's `transpilePackages`.

1. `packages/db/src/index-sync.ts`: `syncProject(db, req: { project; commitSha; records: SyncRecord[]; findings }): Promise<IndexSyncResponse>`.
   - `SyncRecord` is a `RecordRow` plus `links: { type; to; version? }[]`.
   - One transaction: upsert every record with `deleted_at` null; set `deleted_at = now()` on the project's records not in the push; delete and re-insert the project's `record_links`; insert an `index_syncs` row (`ok` = no findings).
   - Re-running the same push changes nothing but the sync row.
2. `packages/db/src/ids.ts`: `allocateIds(db, req: AllocateIdsRequest): Promise<string[]>`. One statement:

   ```sql
   insert … on conflict (project, prefix) do update
     set last = greatest(id_counters.last, $maxInTree) + $count
   returning last
   ```

   Return `last-count+1 … last`, formatted with `formatId`. `count` must be 1 to 200.
3. `packages/db/src/query.ts`: `createIndexQueries(db): IndexQueries`.
   - Deleted records are never returned.
   - `listRecords` filters on `type`, `status`, and header fields `confirmation` and `links.from_source` (jsonb).
   - `search`: case-insensitive match on title and body, limit 20.
   - `traceUp`: follows `record_links` from the record, depth 5 by default, no node visited twice. `via` is the link type.
   - `traceDown`: follows reverse links (`to_id`), same rules.
   - `latestSync`: the newest `index_syncs` row.
4. `packages/db/src/cards.ts`: `cards(project?)` per K8.
   - `confirm_claims`: one per source with claims whose `confirmation` is `pending` and that have a `said_by` link.
   - `approve`: records in `review` with no `approval` field.
   - `broken_link`: `dead_link` findings from each project's latest sync.
   - `createIndexQueries` exposes it as `cards`.
5. Export the new modules from `packages/db/src/index.ts`.
6. Dashboard: `apps/dashboard/lib/index-api/`.
   - `parseSyncPush(body)` builds on `parseRecordsPush` in `lib/records/ingest.ts`, and also accepts `records/sources/<SRC>/meta.yaml` (YAML, no body). It extracts links from `header.links` (`BR-01@2` → `{ to: "BR-01", version: 2 }`), and caps files at 2,000 and each at 200 KB.
   - Route handlers, all `POST`, each needing `Authorization: Bearer <INDEX_TOKEN>` (use `authorized` from `lib/otel/handlers.ts`; 401 without it, 503 when `INDEX_TOKEN` or the database isn't configured, 400 with a plain message on a bad body):
     - `app/api/index/sync/route.ts`
     - `app/api/ids/route.ts`
     - `app/api/index/query/route.ts`
   - Leave `/api/records` alone; S6 retires it.

## Tests (PGlite)

- `index-sync`:
  - First sync stores records and links.
  - A second sync without a file marks it deleted, and it disappears from queries.
  - The same push twice gives the same rows.
  - Findings set `ok: false`.
- `ids`:
  - First call continues from `maxInTree`.
  - Twenty parallel calls of count 3 give 60 distinct IDs.
  - CLM IDs have 4 digits.
- `query`:
  - On a synced copy of `fixtures/f01` plus three claims, a BR and an APR: `traceUp(BR)` reaches the claims, their source and stakeholders.
  - `traceDown(CLM)` reaches the BR.
  - `listRecords` with `confirmation: confirmed` filters correctly.
  - `search` finds by body text.
- `cards`: each kind appears when it should, and goes away after the change that clears it.
- Routes: 401 without a token, 401 with a wrong one, 200 with `test-token`, 400 on a bad body. `meta.yaml` is accepted and a path outside `records/` is refused.
