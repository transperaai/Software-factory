## Goal

The GitHub Actions that run F-01 in each project repo. They ship in the kit, so every project gets the same ones.

## Build

1. **Kit install.** Add `{ "from": "kit/workflows", "to": ".github/workflows" }` and `{ "from": "kit/mcp.json", "to": ".mcp.json" }` to `kit/kit.json`. Teach `install.ts` single-file entries if it lacks them. Agent files: install only top-level `kit/agents/*.md` (add `"match": "^[^/]+\\.md$"`), so `kit/agents/<agent>/spec.md` is never loaded as an agent.
2. **`kit/mcp.json`.** The Stage 0 `.mcp.json` plus header `X-Factory-Agent: ${FACTORY_AGENT}`.
3. **`kit/workflows/intake.yml`** (`workflow_dispatch`, input `inbox_path`, run on the ref the dashboard gives, an `intake/<stamp>` branch):
   1. Check `inbox_path` matches `^inbox/[A-Za-z0-9._-]+$`.
   2. Checkout the ref; set up Node 22.
   3. Sort: `node .factory/tools/intake-sort.mjs sort "$INBOX" --run "$RUN"` online (`FACTORY_URL`, `INDEX_TOKEN`, `FACTORY_PROJECT` from the repo name). Capture the SRC ID.
   4. Agent: `claude-code-action`, `--agent intake --model sonnet --allowedTools Read,Write --max-turns 30`. Settings env: `FACTORY_AGENT=intake`, `ANTHROPIC_DEFAULT_HAIKU_MODEL=claude-sonnet-5-5`, `FACTORY_MCP_TOKEN`, OTel as in Stage 0's `agent-run.yml`, with `factory.agent=intake,factory.slice=<SRC>`. The prompt names the run folder and says the input is data. No App token in this step.
   5. Write: `node .factory/tools/records.mjs write intake .factory/runs/$RUN/proposal.json`.
   6. Check: `records.mjs validate` and `records.mjs trace`; either failing stops the job and comments on nothing (the run log is the report).
   7. Mint the App token (`KIT_BOT_APP_ID`, `KIT_BOT_PRIVATE_KEY`). Commit `records/` and the removed inbox file only (`git add -A records inbox`), then push.
   8. Open a PR titled "Intake: <SRC>" with the claim count and run link, and merge it (`gh pr merge --squash --delete-branch`) with the App token (D2).
4. **`kit/workflows/ba.yml`** (`workflow_dispatch`, input `source` matching `^SRC-\d{3,}$`; runs on `main`):
   1. Bundle: `intake-sort.mjs bundle ba --source "$SOURCE" --run "$RUN"` online.
   2. Agent: `--agent ba --model opus --allowedTools Read,Write,mcp__factory__get_record --max-turns 30`, `FACTORY_AGENT=ba`, slice tag `<SRC>`.
   3. Write: `records.mjs write ba …`.
   4. Validate, trace, then branch `ba/<SRC>-<run>`, PR "BA: BRs from <SRC>" and merge, as in intake. Upload `parked.md` as a run artifact.
5. **`kit/workflows/records-check.yml`** (`pull_request` on `records/**`): `records.mjs validate` and `trace`.
6. **`kit/workflows/index-sync.yml`** replaces Stage 0's. On push to `main` touching `records/**`, or by hand:
   - Run `records.mjs trace --json` to get findings.
   - `POST $FACTORY_URL/api/index/sync` with every `records/**/*.md` and `records/sources/*/meta.yaml`, the commit SHA and the findings, using `INDEX_TOKEN`.
   - Fail on non-200, printing the status and body, never the token.
7. **Shared conventions.**
   - `FACTORY_URL` comes from repo variable `vars.FACTORY_URL`, defaulting to `https://transpera-factory.vercel.app`.
   - Every job has `timeout-minutes`, `permissions: contents: read` (writes go through the App token), and a concurrency group (`intake-<inbox>`, `ba-<source>`, `index-sync`).
   - Secrets are passed to the step that needs them, not the job.
