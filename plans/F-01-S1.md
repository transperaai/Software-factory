## Goal

The deterministic tools every F-01 step uses to read, write, number, check and approve records. Scripts, not agents: same input, same output, safe to re-run.

## Build

Add `@factory/schemas: workspace:*` and `yaml` to `packages/records/package.json`, and `esbuild` (same version as `packages/schemas`) as a dev dependency.

1. `src/io.ts`
   - `parseRecord(content: string): { header: RecordHeader; body: string }`. Throws on a missing or unclosed header.
   - `serializeRecord(header: RecordHeader, body: string): string`. Key order: `id, type, title, status, version, created_by, approval`, then other fields in their existing order, then `links` last. Ends with one newline. `parseRecord(serializeRecord(h, b))` round-trips.
   - `readProject(dir): Map<string, { path: string; header: RecordHeader; body: string }>` over `records/**/*.md` and `records/sources/*/meta.yaml` (meta has no body). Keyed by ID. A second file with the same ID is kept in a separate `duplicates` list (return `{ records, duplicates }`).
   - `recordPath(prefix, id)`: `records/<folder>/<id>.md` using `RECORDS` from `@factory/schemas`; sources are `records/sources/<id>/meta.yaml`.
2. `src/allocate.ts`
   - `allocateIds(opts: { project; prefix; count; dir; url?; token?; fetch? }): Promise<string[]>`.
   - `maxInTree` is the highest number of that prefix in `readProject(dir)`.
   - With `url` and `token`: `POST {url}/api/ids` with `AllocateIdsRequest`, return `ids`. Any non-200 throws with the status, never the token.
   - Without them (offline: tests, evals): `maxInTree + 1 … + count`, formatted with `formatId`.
3. `src/writer.ts`
   - `writeIntake(dir, proposal: IntakeProposal, opts: { allocate; date })`. Validate the proposal against `schemas/intake-proposal.schema.json` (Ajv 2020). For each claim with `quote: verbatim`, the `words` (whitespace-normalised) must appear in the line of `records/sources/<SRC>/text.md` named by `location` (`L<n>`), or anywhere in the file when `location` is a timestamp. Any failure rejects the whole proposal with every problem listed, and writes nothing. Then allocate CLM IDs and write one CLM per claim: `title` is the first 80 characters of `words` (cut at a word break), `status: draft`, `version: 1`, `created_by: agent:intake`, `confirmation: pending`, `links.from_source: [SRC]`, `links.said_by: [SH]` only when not null; `flags` and `note` go in the body. Returns written paths.
   - `writeBa(dir, proposal: BaProposal, opts)`. Validate against `ba-proposal.schema.json`. Every evidence ID must exist and have `confirmation: confirmed`; otherwise reject and write nothing. Write BR records with `status: review`, `version: 1`, `created_by: agent:ba`, `value`, `priority`, `owner`, `links.evidence`. `parked` asks go to `.factory/runs/<run>/parked.md` (a summary, not a record).
4. `src/validate.ts`: `validateProject(dir, schemaDir): TraceFinding[]`. Kinds: `schema` (via `RecordValidator`), `id_reused` (from `duplicates`), `dead_link` (any link target, version stripped, not in the project; cross-project refs like `ACME:BR-01` are skipped).
5. `src/trace.ts`: `traceCheck(dir): TraceFinding[]`, F-01 rules only:
   - `unconfirmed_evidence`: a BR in `review` or `approved` cites a claim that isn't `confirmed`.
   - `changed_after_approval`: a record with `approval: APR-x` whose `version` differs from the version APR-x `approves`.
   - Also returns `validateProject`'s findings, so one call gives the full list.
6. `src/approve.ts`: `buildApproval(opts): RecordFile[]`.
   - Input: `{ records (from readProject), aprId, kind: "approve" | "confirm", targets: string[], decision: "approved" | "rejected" | "changes_requested", approver: "SH-00", role: "Delivery lead", date, comment? }`.
   - Output: the APR record (`links.approves: ["<id>@<version>", …]`, `status: approved`, `created_by: human:austin`) plus each changed target.
   - `approve` + `approved`: target gets `status: approved` and `approval: <aprId>`. `approve` + other decisions: target goes to `status: draft`.
   - `confirm` + `approved`: each claim gets `confirmation: confirmed`. `confirm` + `rejected`: `confirmation: rejected`.
   - Versions never change. Throws if a target is missing.
7. `src/cli.ts`, bundled to `kit/tools/records.mjs` by `build-kit-tool.mjs` (copy the schemas pattern, with `--check`). Commands, each exiting non-zero on failure with readable errors:
   - `write intake|ba <proposal.json> [--date YYYY-MM-DD]`
   - `validate`
   - `trace [--json]`
   - `allocate <PREFIX> <count>`
   - Online mode uses env `FACTORY_URL`, `INDEX_TOKEN`, `FACTORY_PROJECT`; offline otherwise. The schema dir is `.factory/schemas` when present, else `schemas/`.
8. Hook `kit/hooks/validate-records.mjs` (source `packages/records/src/hook.ts`, bundled by the same build script). PostToolUse on `Write|Edit|MultiEdit`: a file under `records/` (`.md` or `meta.yaml`) is checked against its schema; a file named `proposal.json` under `.factory/runs/` is checked against the proposal schema matching `input.json`'s `agent` in the same folder. Problems go to stderr with exit 2, so the agent sees them and fixes them. Add the hook to `kit/settings.json` next to the existing PreToolUse entry.
9. Exports: add `export * from` lines for the new modules to `src/index.ts`. Add `build:kit-tool` and `build:kit-tool:check` scripts.

## Tests (`packages/records/src/*.test.ts`, on temp copies of `fixtures/f01`)

- `io`: round-trip; key order; `readProject` finds `.md` and `meta.yaml`; duplicate IDs reported.
- `allocate`: offline continues from the highest ID (fixture has SH-02, so the next SH is SH-03); online sends `maxInTree` and returns the server's IDs (fake `fetch`); non-200 throws without the token in the message.
- `writer`: writes valid CLM records from a good proposal; rejects a claim whose words aren't at its line, and writes nothing; rejects a BR citing a pending claim; written records pass `validateProject` with no findings.
- `validate`: dead link, reused ID, bad header each produce one finding of the right kind.
- `trace`: unconfirmed evidence; changed after approval; a clean fixture gives `[]`.
- `approve`: approve and confirm outputs pass the schemas; rejected BR goes to draft; missing target throws.
- `hook`: blocks a bad record and a bad proposal (exit 2), allows a good one and unrelated files.
- `kit-tool`: `kit/tools/records.mjs` and `kit/hooks/validate-records.mjs` are up to date (like `packages/schemas/test/kit-tool.test.ts`).
