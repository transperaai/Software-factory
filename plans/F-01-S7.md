## Build

New dependencies: `@octokit/rest` and `@octokit/auth-app` (maintained; CLAUDE.md "Use, hook or build").

1. **`lib/github-app.ts`.**
   - `appOctokit(repo)` makes an installation client for `transperaai/<repo>` from `KIT_BOT_APP_ID` and `KIT_BOT_PRIVATE_KEY`. Accept the key with real or `\n`-escaped newlines.
   - `commitFiles(repo, { branch, message, files: RecordFile[], deletes?: string[] })` makes one commit through the git data API on a new branch from `main`.
   - `openAndMerge(repo, branch, title, body)` opens a PR and squash-merges it, deleting the branch (D2).
   - `dispatch(repo, workflow, ref, inputs)`.
2. **`lib/approvals.ts`**: the approval recorder.
   - `recordDecision({ project, kind, targets, decision, comment }, deps)`:
     1. Read targets and the APR counter's tree max from the index (`IndexQueries`), and allocate the APR ID (`allocateIds`, S3).
     2. Build files with `buildApproval` (S1).
     3. `commitFiles` on `approval/<APR>`, then `openAndMerge`.
     4. After a `confirm` with `approved`, `dispatch` `ba.yml` with `{ source }` on `main`.
   - `deps` are injected (`queries`, `allocate`, `github`, `now`) so tests need no network.
3. **`lib/inbox.ts`**: `uploadSource({ project, name, bytes })`.
   - Accept `.txt`, `.vtt` and `.md` up to 1 MB, with the name cleaned to `[A-Za-z0-9._-]`.
   - Commit to `inbox/<yyyymmdd-hhmmss>-<name>` on branch `intake/<stamp>`, then `dispatch` `intake.yml` with `{ inbox_path }` on that branch (K1, K9).
4. **Pages.** Each checks sign-in and `isAllowed` the way `page.tsx` does, and server actions check it again.
   - `/`: the existing page with a "Needs you" card list at the top, from `queries.cards()`.
     - `confirm_claims` lists each claim's words and speaker with a tick box (all ticked), and buttons **Confirm** and **Reject**. Unticked claims are left pending.
     - `approve` shows the record's title, value and evidence quotes, a comment box, and **Approve** and **Reject**.
     - `broken_link` links to the record's thread page.
   - `/inbox`: project picker (projects that have records in the index), file input, and a list of the latest sources with their claim counts.
   - `/thread/[project]`: a table of BRs (ID, title, status, approval).
   - `/thread/[project]/[id]`: the BR, then its evidence claims. Each claim shows its quote, speaker name, source ID and location, from `traceUp`. Add a breadcrumb back to the table.
   - Server actions live in `app/actions.ts`.
5. **`app/api/e2e/`** (`inbox`, `cards`, `act`, `thread/[id]`): the same functions as the pages, for the automated test.
   - Bearer `FACTORY_API_TOKEN` is checked in constant time, as `lib/mcp/server.ts` does.
   - Every route refuses any project except `factory-e2e`, with 403.
   - 503 when the token isn't configured.
6. Until S1 and S3 are on `f01`, call `buildApproval`, `allocateIds` and `createIndexQueries` through one `lib/deps.ts` file and note it in your reply. Tests use fakes either way.

## Tests (vitest; GitHub mocked at the Octokit boundary only)

- `approvals`:
  - Approving BR-01 commits an APR plus the updated BR on `approval/APR-0001`, then merges.
  - Confirm dispatches `ba.yml` with the source.
  - Reject doesn't dispatch.
  - A missing target throws before any GitHub call.
- `inbox`:
  - Refuses `.mp3` and files over 1 MB.
  - Cleans names.
  - Commits to the right path and branch, then dispatches with that path.
- `github-app`: both private-key forms parse (a generated test key, never a real one).
- Pages and actions: signed-out and wrong-account requests are redirected; actions refuse them too.
- `e2e` routes:
  - 401 without a token.
  - 403 for `factory-test-project`.
  - 200 for `factory-e2e` with fakes.
- Rendering: the card list and thread pages render from a fake `IndexQueries` built from `fixtures/f01` plus a confirmed claim, a BR and an APR.
