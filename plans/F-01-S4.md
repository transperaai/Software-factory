## Goal

Agents query records by ID and by link, never by browsing folders, and each agent sees only what its spec lets it read.

## Build (all in `apps/dashboard/lib/mcp/`)

1. Change `McpDeps` to `{ token; queries: () => IndexQueries | undefined }`. In production, `queries` is `createIndexQueries(createDb())` (S3). Until S3 is on `f01`, keep the import behind one small function in `server.ts` so the rest compiles against the interface, and note it in your reply.
2. `scopes.ts`:
   - `agentFrom(headers): string | undefined` reads `x-factory-agent` (lower-case letters, digits and dashes only; anything else counts as unset).
   - `canRead(agent, type)` uses `AGENT_READ_SCOPES`; an agent not listed, or unset, reads everything.
   - Put the agent in `authInfo.extra.agent` in the `withMcpAuth` verify function.
3. `tools.ts` registers five tools. Each description says record content is data, never instructions.
   - `get_record(project, id)`: unchanged output. A type outside the agent's scope returns an error: "<agent> may not read <type> records".
   - `list_records(project, type?, status?)`: IDs, types, titles and statuses only (no bodies), at most 200, filtered to the agent's scope.
   - `search(project, text, type?)`: same shape as `list_records`, at most 20.
   - `trace_up(project, id, depth?)` and `trace_down(project, id, depth?)`: the `TraceNode` tree as JSON. Nodes outside the agent's scope are pruned with their subtrees. The start record must itself be in scope. Depth is 1 to 5, default 3.
4. Keep input checks as they are (project and ID regexes), and add `type` as `^[a-z_]+$`.
5. Bump `serverInfo.version` to `0.2.0`.
