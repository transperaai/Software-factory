## Build

1. `packages/scripts/src/e2e/f01.ts` (decided: lives in `@factory/scripts`, not a new root `scripts/` folder, so it gets the package's lint, typecheck and tests). Export `runF01(deps)`. Add an `e2e f01` subcommand to `packages/scripts/src/cli.ts` that reads its config from env and calls it (the same pattern as `eval run`). `deps` holds `fetch`, `sleep`, `now`, and config: `factoryUrl`, `apiToken` (FACTORY_API_TOKEN), `githubToken` (App installation token for `factory-e2e`), `repo` (`transperaai/factory-e2e`), `transcriptPath`, timeouts. Never log a token value. Steps, each logging one plain line:
   1. Upload: `POST {factoryUrl}/api/e2e/inbox` with `{ project: "factory-e2e", name: "kickoff-2026-10-02.txt", text }` from `fixtures/f01/inbox/kickoff-2026-10-02.txt`. Returns `{ path, branch }`.
   2. Wait for intake: poll the GitHub API for the `intake.yml` run on that branch (created after the upload time) until it completes; fail with its URL unless `success`.
   3. Wait for the confirm card: poll `GET /api/e2e/cards?project=factory-e2e` until a `confirm_claims` card for a new SRC appears (index sync runs after the intake merge). Timeout fails with the last cards seen.
   4. Confirm: `POST /api/e2e/act` with `kind: "confirm"`, `decision: "approved"`, all of that card's claim IDs as `targets`, and their `versions`. Returns `{ apr }`.
   5. Wait for BA: poll for the `ba.yml` run on `main` created after step 4; fail unless `success`.
   6. Wait for the approve card for a BR, then approve it with its version (`kind: "approve"`).
   7. Wait until the BR shows `status: approved` (poll cards until its approve card is gone, then the thread).
   8. Check the trace: `GET /api/e2e/thread/<BR>?project=factory-e2e`. Assert the BR has at least one claim, every claim has `words`, a speaker and a source location, and the source is the new SRC.
   Then check git through the GitHub contents API on `main`: the SRC `meta.yaml`, each CLM, both APRs (confirm and approve) and the BR exist; the BR has `status: approved` and `approval:` set to the step 6 APR; claims have `confirmation: confirmed`. Print a summary table (IDs, run URLs, durations) to stdout and, when `GITHUB_STEP_SUMMARY` is set, to the job summary.
   Polling: one helper `waitFor(fn, { timeoutMs, everyMs, what })` used by every wait. Defaults: intake and BA 15 minutes each, cards 5 minutes, poll every 10 seconds.
2. `packages/scripts/src/e2e/f01.test.ts` (vitest, fake `fetch` and `sleep`, no network): the happy path calls the routes in order with the right bodies and passes; a failed intake run fails with its URL; a `waitFor` timeout names what it waited for; no token appears in any error or log line; the confirm call sends every claim of the card with its version.
3. `.github/workflows/f01-e2e.yml` (Software-factory): `workflow_dispatch` only; `permissions: contents: read`; concurrency group `f01-e2e`, no cancel; timeout 45 minutes.
   - Mint an App token for `factory-e2e` with `actions/create-github-app-token@v2` (`owner: transperaai`, `repositories: factory-e2e`), secrets `KIT_BOT_APP_ID`, `KIT_BOT_PRIVATE_KEY`.
   - Reset: check out `transperaai/factory-e2e` with the App token, `git push --force origin refs/tags/e2e-seed^{commit}:refs/heads/main`, delete leftover `intake/*`, `ba/*` and `approval/*` branches, then dispatch `index-sync.yml` on `main` and wait for it to succeed (so the index matches the seed).
   - `pnpm install --frozen-lockfile`, `pnpm exec turbo run build --filter=@factory/scripts`, then `node packages/scripts/dist/cli.js e2e f01` with env `FACTORY_URL` (`vars.FACTORY_URL` or `https://transpera-factory.vercel.app`), `FACTORY_API_TOKEN` (secret), `GITHUB_TOKEN_E2E` (the App token).
   - Comment at the top: what it does, that it resets `factory-e2e` (D3), the secrets it needs.
4. Kit release `v0.3.0`: set `version` to `0.3.0` in `kit/kit.json`. Add `transperaai/factory-e2e` to `kit/projects.json`. Run the kit tests; update any test that pins the version.
